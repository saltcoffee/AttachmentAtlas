# Attachment Atlas

查找重复图片、清理闲置附件，同时维护 Obsidian 中的图片引用。

[English](README.md) · [反馈问题](https://github.com/saltcoffee/AttachmentAtlas/issues) · [更新记录](CHANGELOG.md)

## 功能

- **查找完全重复的图片**：识别名称、位置不同但内容完全一致的图片，选择保留项，更新受支持的引用后回收重复副本。
- **清理未引用图片**：查看未发现引用的图片，确认后将选中的资源保存在插件自己的回收区。
- **查看图片引用**：浏览图片大小、尺寸，以及 Markdown 笔记、Canvas 和 Excalidraw 绘图中的引用位置。
- **操作前预览**：先查看文件清单和笔记改动，再确认执行；可限定处理目录，并保护不希望回收的文件。
- **恢复清理操作**：从「操作历史」还原原图和引用；保留有冲突的后续编辑，全部恢复成功后自动清除该操作的恢复数据。
- **管理恢复空间**：在「操作历史」查看恢复数据占用，预览并确认后，永久清理不再需要的操作记录和恢复副本。

支持静态 **PNG、JPEG 和 WebP** 图片。适用于 Obsidian 桌面端，全部处理在本地完成。

界面自动跟随 Obsidian 的语言设置：中文（包括繁体中文设置）显示简体中文，其他所有语言显示英文。更改 Obsidian 语言后，请重新加载应用以更新命令名称和已打开的视图。

## 安装

当前为开发构建，尚未上架社区插件市场，需要手动安装。

1. 安装 Node.js 22+ 和 npm，在项目目录中运行：

   ```sh
   npm ci
   npm run package
   ```

2. 将生成的 `release/attachment-atlas/` 文件夹复制到知识库的 `.obsidian/plugins/` 目录。
3. 重新加载 Obsidian，在「设置 → 第三方插件」中启用 **Attachment Atlas**。

如需使用合成图片体验，运行 `node scripts/dev-vault.mjs`，在 Obsidian 中以知识库打开生成的 `dev-vault/`，再启用本地插件。

正式创建版本后，[GitHub Releases](https://github.com/saltcoffee/AttachmentAtlas/releases) 也会提供 `attachment-atlas-<版本>.zip`。解压得到 `attachment-atlas/` 文件夹，按上述第 2–3 步安装即可；版本页面同时展示更新说明和独立的插件文件。

## 使用

点击侧边栏图标，或通过命令面板运行 **Attachment Atlas: 打开图片管理器**，然后点击 **扫描当前库** 开始扫描。

### 合并重复图片

1. 打开 **完全重复**，查看重复图片组。
2. 选择要保留的图片，点击 **预览合并**。
3. 检查文件清单和引用改动，确认后执行。

只有字节完全一致的图片才会被归为重复项。恢复副本校验成功、受支持的引用更新完成后，才移除多余图片的原路径。回收的图片字节统一保存在 `.attachment-atlas-recovery/`。

Excalidraw 引用仅做读取分析，不修改绘图文件。被绘图使用的图片必须保留；管理器会优先推荐保留该副本，以便合并其他符合条件的重复副本。

### 清理未引用图片

1. 打开 **未引用**。
2. 勾选需要回收的图片，点击 **预览回收**。
3. 检查明确的文件路径，确认后执行。

无需等待保护期。引用扫描通过后，可立即勾选符合条件的图片；执行前会再次检查，并保存恢复副本。受保护或引用情况尚未确认的图片无法勾选。

引用检查不完整时，该分类显示为 **疑似未引用**，合并和回收按钮旁会显示禁用原因。点击 **查看阻塞问题** 定位相关来源，处理后重新扫描。

### 恢复清理操作

打开 **操作历史**，找到对应操作，点击 **预览恢复**。恢复时先还原原图，再还原引用；全部恢复并校验成功后，自动永久删除该操作的恢复副本和历史记录。若文件或笔记与后续编辑冲突，会保留新内容及恢复材料。

如果恢复已成功，但清除恢复数据失败，操作历史会保留剩余数据供你继续清理；已经恢复的图片和引用保持不变。

### 清理恢复数据

1. 打开 **操作历史**，查看恢复数据总占用及每条记录的大小。
2. 点击单条记录的 **清理恢复数据**，勾选多条后点击 **预览恢复数据清理**，或通过 **清空恢复区** 预览清空全部记录。**选择超过 30 天的记录** 只帮助选择旧记录。
3. 检查路径和大小，勾选永久删除确认项，再执行清理。

只有已完成、已恢复或已完整回滚的记录可以开始清理；未完成、存在冲突或损坏的记录会被保护。清理会永久删除选中记录的图片数据、笔记快照和操作历史，此后无法通过插件恢复这些操作。当前笔记和当前图片不受影响。清理中断后，可在「操作历史」点击 **继续清理**，重新预览并继续清理剩余数据。未恢复的记录不会自动到期删除。

清空整个回收区要求所有记录均可清理；存在受保护记录时需先处理。每次最多处理 100 条记录、10,000 个文件，超过限制时需分批清理。清空后可能保留一个空的 `.attachment-atlas-recovery/` 根目录。

## 设置

| 设置           | 作用                                                               |
| -------------- | ------------------------------------------------------------------ |
| 图片扫描范围   | 限定图片清理目录，留空则包含整个库。                               |
| 优先保留文件夹 | 推荐保留图片时优先选择此目录中的副本；被绘图使用的副本优先级更高。 |
| 受保护路径     | 不允许回收的文件或目录，每行填写一个路径。                         |

路径均相对于当前知识库。即使只清理一个目录，引用检查仍会覆盖全库中受支持的笔记、Canvas 和 Excalidraw 绘图。

## 常见问题

**为什么图片被标记为 待检查？**

来源文件读取失败、链接有歧义或存在不支持的引用格式时，插件会阻止相应清理。当前支持 Markdown 链接、Wiki 链接、Canvas 文件节点、分组背景和文本节点内的 Markdown。Excalidraw Markdown 绘图（压缩或未压缩 JSON）及独立 `.excalidraw` 文件支持只读扫描，被绘图引用的图片会单独保护；格式不受支持或损坏的绘图、Bases 文件仍可能阻塞引用检查。YAML、HTML 中的引用不会自动改写，检测到相关线索时会保护对应图片。`weread://` 等外部应用链接会识别为外部链接。

**为什么清理后磁盘空间没有立即减少？**

回收的图片暂存在 `.attachment-atlas-recovery/`，供后续恢复。检查结果后，可通过 **操作历史 → 清理恢复数据** 或 **清空恢复区** 永久清除；恢复成功也会自动清除对应恢复数据。空间统计为文件逻辑字节，不包含文件系统元数据、同步历史或外部备份。

**插件会使用 `.trash/` 吗？**

不会，回收资源只保存在插件自己的回收区。早期开发构建可能曾在 Obsidian 共用的 `.trash/` 留下副本；本插件不会自动迁移或删除这些已有文件。

## 隐私与恢复数据

无需账户，不发送网络请求，不收集遥测，文件访问限定在当前知识库内。

回收图片与恢复记录统一保存在 `.attachment-atlas-recovery/`，包含原图与受影响的笔记内容，不额外加密；同步和备份行为取决于知识库设置。材料会保留到你恢复对应操作或确认永久清理。
