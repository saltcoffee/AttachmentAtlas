# Attachment Atlas

查找重复图片、清理闲置图片，让 Obsidian 笔记继续引用正确的文件。

Attachment Atlas 帮你查看库内图片、预览清理改动，并从操作历史中恢复。所有处理都在当前知识库内完成，无需账户或网络连接。

[English](README.md) · [安装](#安装) · [快速开始](#快速开始) · [支持开发](#支持开发) · [更新记录](CHANGELOG.md)

## 可以用它做什么

- **合并重复图片**：为内容完全一致的图片选择一个保留副本，更新受支持的引用后，再回收多余副本。
- **查找闲置图片**：查看未检测到引用的图片，自行选择需要回收的文件。
- **查看空间和引用**：浏览图片大小、尺寸与引用位置，按文件大小查看大图片。
- **先预览，再执行**：确认具体文件路径和笔记改动，执行前还会再次检查。
- **恢复清理操作**：从操作历史中还原图片和引用，遇到后续编辑冲突时保护现有内容。
- **管理恢复空间**：查看恢复记录的占用，在不再需要时永久清理选中的记录。

**支持范围**：Obsidian 桌面端 1.13.0 及以上，静态 PNG、JPEG、WebP 图片。界面跟随 Obsidian 语言设置：中文环境显示简体中文，其他语言环境显示英文。

## 安装

### 从社区插件市场安装

在 Obsidian 中打开 **设置 → 第三方插件 → 浏览**，搜索 **Attachment Atlas**，安装后启用。如果市场中暂时还搜索不到，可以使用下面的 GitHub Release 安装方式。

### 从 GitHub Releases 安装

1. 打开 [GitHub Releases](https://github.com/saltcoffee/AttachmentAtlas/releases)，下载同一版本的 `main.js`、`manifest.json` 和 `styles.css`。
2. 在知识库的 `.obsidian/plugins/` 目录下创建 `attachment-atlas` 文件夹，将这三个文件放入其中。
3. 重新加载 Obsidian，在 **设置 → 第三方插件** 中启用 **Attachment Atlas**。

安装后的目录应包含以下文件：

```text
<知识库>/.obsidian/plugins/attachment-atlas/
├── main.js
├── manifest.json
└── styles.css
```

安装已发布版本无需 Node.js 或 npm。GitHub 自动提供的源码 ZIP 和 tarball 不是可安装的插件包；开发者可以运行 `npm run package` 生成本地安装 ZIP。

## 快速开始

1. 点击侧边栏中的 **Attachment Atlas** 图片图标，或通过命令面板运行 **Attachment Atlas: 打开图片管理器**。
2. 点击 **扫描当前库**。扫描只读取图片和引用，不修改笔记或附件。
3. 按需要选择分类：

   | 分类         | 用途                                   |
   | ------------ | -------------------------------------- |
   | **完全重复** | 选择需要保留的副本，预览重复图片合并。 |
   | **未引用**   | 勾选闲置图片，预览回收。               |
   | **大图片**   | 按文件大小从大到小查看图片。           |
   | **待检查**   | 查看图片或引用来源需要处理的具体原因。 |
   | **操作历史** | 恢复清理操作，或管理恢复数据。         |

4. 在预览中核对文件路径和改动，再确认执行需要的操作。

可以通过 **按路径筛选** 缩小显示范围。需要限定扫描的图片目录时，在插件设置中填写 **图片扫描范围**；引用检查仍会覆盖整个知识库中受支持的来源。

## 合并重复图片

1. 扫描后打开 **完全重复**。
2. 查看重复图片组，选择要保留的图片。
3. 点击 **预览合并**，核对即将回收的副本，以及将被更新的引用。
4. 确认文件清单后执行。

例如，`images/photo.png` 与 `notes/photo-copy.png` 的字节完全一致时，可以选择保留 `images/photo.png`。插件会先把受支持的引用更新到保留图片，再回收多余副本。

重复组只包含字节完全一致的文件。尺寸不同、重新压缩或仅在视觉上相似的图片，不会被视为完全重复。

被 Excalidraw 绘图使用的图片必须保留，因为插件不改写绘图文件。管理器会优先推荐保留被绘图引用的副本，以便合并其他符合条件的重复副本。

## 回收未引用图片

1. 扫描后打开 **未引用**。
2. 核对图片路径和引用情况，勾选需要回收的图片。
3. 点击 **预览回收**，确认文件清单后执行。

引用检查通过后即可回收，无需等待保护期。受保护或引用情况尚未确认的图片无法勾选。

如果引用检查不完整，该分类会显示为 **疑似未引用**。合并和回收会暂时禁用，直到阻塞问题解决。点击 **查看阻塞问题**，在 **待检查** 中处理报告的来源后重新扫描。

## 恢复清理操作

1. 打开 **操作历史**，找到需要撤销的操作。
2. 点击 **预览恢复**，核对要还原的图片和引用。
3. 确认后执行恢复。

恢复时先还原原图，再还原引用。遇到后续笔记编辑或路径冲突时，恢复会停止，保留新内容及恢复材料，供你处理冲突。

全部图片和引用恢复并校验成功后，该操作的恢复副本和历史记录会被永久移除。如果图片和引用已恢复，但清除恢复数据失败，操作历史会保留剩余数据供你继续清理，已恢复的图片和引用保持不变。

## 释放恢复区空间

回收会移除图片的原路径，同时将恢复副本保存在 `.attachment-atlas-recovery/`。恢复操作或永久清理恢复数据之前，这些副本仍会占用磁盘空间。

1. 打开 **操作历史**，查看恢复数据总占用与每条记录的大小。
2. 点击单条记录的 **清理恢复数据**，或勾选多条记录后点击 **预览恢复数据清理**。需要清空全部符合条件的记录时，点击 **清空恢复区** 进行预览。
3. 检查路径和大小，勾选永久删除确认项，再执行。

**清理恢复数据会永久删除选中记录中的图片、笔记快照和历史记录，此后无法再通过插件恢复这些操作。** 当前笔记和当前图片不受此操作影响。

未完成或损坏的记录会被保护。清空整个恢复区前需先处理这些记录，其他符合条件的记录仍可单独清理。如果清理中断，点击 **继续清理**，重新预览并完成剩余清理。

记录不会自动到期删除。**选择超过 30 天的记录** 只是帮助选择待检查的记录。每次最多清理 100 条记录、10,000 个文件，超出时需分批处理。清理后可能保留空的 `.attachment-atlas-recovery/` 文件夹。

## 设置

打开 **设置 → Attachment Atlas**，填写相对于知识库的路径，不要以斜杠开头，完成后点击 **保存设置**。

| 设置               | 作用                                                     | 示例                    |
| ------------------ | -------------------------------------------------------- | ----------------------- |
| **图片扫描范围**   | 限定需要检查的图片目录；留空表示整个知识库。             | `Attachments`           |
| **优先保留文件夹** | 为重复组推荐此目录中的副本；被绘图引用的副本优先级更高。 | `Attachments/Keep`      |
| **受保护路径**     | 防止指定文件或目录内的图片被回收；每行填写一个路径。     | `Attachments/Important` |

限定图片扫描范围不会缩小引用检查范围：插件仍会检查整个知识库内受支持的笔记、Canvas 和 Excalidraw 绘图。

## 命令

在 Obsidian 命令面板中搜索 **Attachment Atlas**，可以找到：

| 命令                   | 作用                                                   |
| ---------------------- | ------------------------------------------------------ |
| **打开图片管理器**     | 打开图片管理界面。                                     |
| **扫描库内图片**       | 打开管理器，并按设置中的图片扫描范围扫描。             |
| **扫描当前附件文件夹** | 根据当前笔记及 Obsidian 的附件存放设置确定目录并扫描。 |
| **打开操作历史**       | 查看恢复记录。                                         |

## 引用支持范围

| 来源                                                            | 处理方式                                       |
| --------------------------------------------------------------- | ---------------------------------------------- |
| Markdown 图片链接与 Wiki 链接                                   | 检测引用，合并重复图片时更新受支持的链接。     |
| Canvas 文件节点、分组背景、文本节点中的 Markdown                | 检测引用，合并重复图片时更新受支持的链接。     |
| Excalidraw Markdown 绘图（含压缩数据）及独立 `.excalidraw` 文件 | 只读扫描，不修改绘图；逐个保护被引用的图片。   |
| YAML 与 HTML                                                    | 不改写引用；检测到相关线索时可能保护对应图片。 |

不支持或损坏的来源，包括绘图和 Bases，可能阻塞引用检查。请先在 **待检查** 中查看原因。外部应用及隐藏配置不在扫描覆盖范围内。

## 常见问题

**为什么合并或回收按钮无法点击？**

查看按钮旁的具体原因。常见情况包括引用检查不完整、图片受保护、其他任务正在运行，或存在未完成的恢复操作。在 **待检查** 或 **操作历史** 中处理报告的问题后重新扫描。

**为什么修改笔记或图片后，之前的扫描结果消失了？**

库内文件发生变化后，旧扫描结果会失效。请先重新扫描，再预览下一次操作，让处理计划基于当前文件和引用。

**大图片分类可以压缩或转换图片吗？**

这个分类用于按大小查看图片。插件当前管理静态 PNG、JPEG、WebP 图片，不提供压缩或格式转换，也不清理 PDF、视频等其他类型的附件。

**插件会使用 Obsidian 的 `.trash/` 或系统废纸篓吗？**

会。插件先在 `.attachment-atlas-recovery/` 保存并校验恢复副本，再通过 Obsidian 文件管理器移除每个原文件，遵循你的删除偏好。根据该偏好，Obsidian 可能在 `.trash/` 或系统废纸篓中另存一份。插件不会管理或清空这两处回收站。

**为什么清理后磁盘空间没有立即减少？**

恢复副本仍然占用空间。确认结果后，可通过 **操作历史 → 清理恢复数据** 永久移除。Obsidian 或系统废纸篓中的副本需要另行管理。空间统计仅包含插件恢复文件，不包含回收站、文件系统元数据、同步历史或外部备份。

**如何切换界面语言？**

修改 Obsidian 的语言后重新加载应用，命令名称和已打开的视图才会更新。中文环境显示简体中文，其他语言环境显示英文。

## 隐私与恢复数据

Attachment Atlas 只在当前知识库内处理文件，无需账户，不发送网络请求，不收集遥测。

扫描会枚举知识库文件路径，以便在限定图片扫描范围时仍能检查全库受支持的引用来源。Node.js 文件系统调用仅通过 `lstat()` 读取路径元数据，用于拒绝知识库根目录及访问路径中的符号链接；文件内容读写和删除均使用 Obsidian API。剪贴板权限只在你点击 **复制恢复目录路径** 时写入相对于知识库的目录路径，插件不会读取剪贴板内容。

恢复数据包含原图、受影响的笔记内容和操作记录，统一保存在 `.attachment-atlas-recovery/` 中，不额外加密。同步和备份行为取决于知识库设置。请保留这些材料，直到恢复对应操作或确认永久清理。
